# 🥕 당근마켓 클론 코딩
## First Team Project (F1팀)

Figma로 제공된 당근마켓 디자인 시안을 기반으로 웹 페이지의 UI를 구현하고,
제공된 API를 활용하여 상품 데이터를 연동한 당근마켓 클론 코딩 프로젝트입니다.

## 📌 프로젝트 소개

본 프로젝트는 Figma로 제공된 당근마켓 디자인 시안을 참고하여
실제 웹 페이지의 UI와 주요 기능을 구현하는 것을 목표로 진행했습니다.

HTML, CSS, JavaScript를 활용하여 Figma에 구현된 화면을 웹 페이지로 제작했으며,
제공된 API를 활용하여 상품 데이터를 불러오고 화면에 동적으로 표시했습니다.

당근마켓의 주요 기능을 참고하여 상품 목록 조회, 상품 상세 조회,
상품 검색, 마이페이지, 채팅 등의 기능을 구현했습니다.

또한 4명의 팀원과 GitHub를 활용하여 코드를 관리하고,
각자 기능을 분담하여 프로젝트를 진행하면서 협업 및 Git 사용 경험을 쌓았습니다.

## 🛠 기술 스택

- HTML5, CSS3, Vanilla JavaScript (프레임워크·라이브러리 없음)
-  Node.js, Express — 클라이언트 요청을 실제 API 서버로 중계하는 프록시 서버
- **외부 API**: [Nominatim (OpenStreetMap)](https://nominatim.org/) — 동네인증 페이지에서 GPS 좌표 ↔ 주소 변환
- **인증**: `localStorage`에 토큰 저장, `Authorization: Bearer` 헤더로 인증 요청
- 사용한 CSS/JS 기법
  - `fetch` 기반 REST API 통신, `async/await`
  - `debounce`(검색어 입력, 동네 검색)로 불필요한 API 호출 방지
  - `IntersectionObserver` 대신 `scroll` 이벤트 + 임계값으로 구현한 무한 스크롤 (중고거래 목록)
  - `FormData` 기반 이미지 업로드
  - CSS `Flexbox` / `Grid` 레이아웃, `clamp()`를 이용한 유동적 반응형 사이징
  - `position: relative/absolute`를 이용한 드롭다운(검색 결과, 프로필 메뉴) 앵커링
  - 모달 `hidden` 속성 토글 방식 (JS 최소화)

### 공통 (Header)
 
- **로그인 상태에 따른 UI 분기**: `localStorage`에 토큰이 있는지로 로그인/로그아웃 버튼, "동네인증" 메뉴 노출 여부를 전환합니다.
- **반응형 프로필 메뉴**: 데스크톱에서는 프로필 클릭 시 마이페이지로 바로 이동하고, `matchMedia(max-width: 768px)`인 모바일에서는 드롭다운 메뉴(마이페이지/채팅/로그아웃)가 열리도록 분기했습니다. 바깥 영역 클릭이나 화면 확대 시 자동으로 닫힙니다.
- **모바일 검색 토글**: 좁은 화면에서는 돋보기 아이콘을 눌러야 검색창이 펼쳐지도록 했고, 검색 폼 제출 시 `search.html?keyword=`로 이동합니다.
- **현재 페이지 강조**: `location.pathname`을 확인해 중고거래/동네인증 등 현재 위치에 해당하는 네비게이션 항목에 주황색을 강조 표시합니다.


### 🧡 Onboarding

- `GET /api/products?page=1`로 상품을 받아와 상위 8개만 잘라 인기매물 카드로 렌더링합니다.
- 1200px / 768px / 480px 3단계 브레이크포인트로 히어로·동네소개·푸터 영역을 단계적으로 조정했습니다.
- CSS Grid와 `order` 속성만으로 HTML 변경 없이 아이콘·텍스트·이미지 배치를 화면 크기별로 재구성했습니다.
- Google Play·App Store 버튼을 `<a target="_blank">`로 구현해 실제 스토어로 새 탭 연결됩니다.


### 📍 Location (동네인증)

- GPS로 현재 좌표를 얻어 Nominatim reverse geocoding으로 주소(시/구/동)를 변환하고, 실패 시 기본 위치로 대체합니다.
- 동네를 직접 검색하면 300ms 디바운스 후 Nominatim search API로 후보 목록을 보여줍니다.
- 직선거리 대신 시/구/동 문자열을 비교하는 방식으로 동네 일치 여부를 검증해, 면적이 넓은 구에서 발생하던 오탐지를 해결했습니다.
- 현재 위치와 다른 동네를 설정하려 하면 확인 모달을 띄우고, 최종 확정된 동네는 `PATCH /api/auth/me`로 저장합니다.

### 🔑 Login / Register

- 로그인·회원가입 폼은 동일한 클래스명을 공유해 레이아웃과 스타일 코드를 재사용했습니다.
- 로그인은 `POST /api/auth/login` 성공 시 토큰을 저장하고 온보딩으로, 회원가입은 닉네임·비밀번호 확인을 검증한 뒤 `POST /api/auth/signup` 성공 시 로그인 페이지로 이동합니다.
- 768px 이하에서는 폼 너비를 `100%`로 바꾸고 폰트·패딩을 축소해 화면에 맞춥니다.


### 🔍 Search

- URL의 `keyword` 쿼리로 상품을 검색하고, 헤더 검색창에도 같은 검색어를 유지합니다.
- `GET /api/products?q=`로 결과를 받아 카드로 렌더링하며, 결과가 없으면 안내 문구를 보여줍니다.
- 이전/다음 버튼과 페이지 번호로 페이지네이션을 구현했고, 카드 클릭 시 상세 페이지로 이동합니다.
- 결과 그리드는 4열 고정에 `justify-content: center`를 줘서 결과가 적을 때도 가운데 정렬됩니다.

### 🛍️ Trade (목록)

- 스크롤이 하단 300px 이내에 도달하면 다음 페이지를 요청하는 무한 스크롤을 구현했습니다.
- 로딩 중 중복 요청 방지 플래그와 서버의 `hasNext` 값으로 더 불러올 데이터가 없으면 요청을 멈춥니다.
- 인기매물 그리드는 화면 크기에 따라 4열 → 3열 → 2열로 줄어들고, 우측 하단 플로팅 버튼으로 글쓰기 페이지로 이동합니다.
- **페이지 자동 증가**: 응답의 `data.hasNext`로 다음 페이지 존재 여부를 저장하고, 성공적으로 상품을 그린 뒤 `currentPage`를 1씩 증가시켜 다음 스크롤 시 이어지는 페이지를 요청하게 했습니다.


### 🛍️ Trade-post 

- 상품 상세 정보(제목·가격·설명·거래 장소·판매자)를 API 응답으로 채웁니다.
- 로그인 사용자와 판매자 ID를 비교해 본인 글일 때만 수정/삭제 버튼을 보여줍니다.
- "채팅하기" 클릭 시 채팅방을 생성해 바로 채팅 페이지로 이동하고, 삭제는 확인창을 거쳐 처리합니다.
- **삭제/수정 보호**: 삭제는 `confirm()` 확인 후 `DELETE /api/products/:id`를 호출하고, 수정 버튼은 클릭 시점에도 다시 한번 소유자 여부를 확인해 아니라면 이동을 막고 안내 문구를 띄웁니다.
- **뒤로가기 버튼**: 브라우저 히스토리가 있으면 `history.back()`으로 돌아가고, 없으면(다른 사이트에서 바로 진입한 경우 등) 목록 페이지로 이동시켜 항상 갈 곳이 있도록 처리했습니다.

### ✍️ Write

- URL의 `id` 파라미터 유무로 등록/수정 모드를 구분해 하나의 폼을 재사용합니다.
- 이미지는 `FormData`로 먼저 업로드해 URL을 받아온 뒤 나머지 정보와 함께 등록/수정 API로 전송합니다.
- 수정 모드는 작성자 본인 여부를 다시 확인해, 아니면 상세 페이지로 돌려보냅니다.
- **입력값 검증과 저장**: "완료" 클릭 시 제목과 가격이 비어있으면 저장을 막고, 가격은 정규식(`replace(/[^0-9]/g, "")`)으로 숫자 이외 문자를 제거해 순수 숫자만 전송합니다. `editId` 여부에 따라 `PATCH /api/products/:id`(수정) 또는 `POST /api/products`(신규)로 분기해서 저장하고, 성공하면 해당 상품의 상세 페이지로 이동합니다.



### 💬 Chat
 
- WebSocket 없이 요청 기반으로 동작하며, 채팅방을 열 때 방 정보와 메시지 목록을 병렬로 조회합니다.
- 메시지 전송 시 API 응답을 받아 화면에 즉시 반영하고 채팅방 목록도 함께 갱신해, 새로고침 없이 최신 상태를 유지합니다.
- 연속된 같은 발신자의 메시지는 아바타를 한 번만 보여주는 방식으로 카카오톡류 채팅 UI를 구현했습니다.
- 모바일에서는 목록 화면과 대화 화면을 전환하며 하나씩만 보여줍니다.

## 트러블슈팅
 
- **GPS 위치와 검색 위치 비교 오류**: 직선거리(Haversine) 기준으로 동네 일치 여부를 판단했더니, 면적이 넓은 구(예: 동남구)에서는 실제로 그 구 안에 있어도 중심점까지의 거리가 기준치(2km)를 넘어 "너무 멀다"고 잘못 판정되는 문제가 있었습니다. → 좌표 거리 대신 시/구/동 주소 문자열을 직접 비교하는 방식으로 변경해 해결했습니다.
- **헤더 검색창에서 검색 페이지로 이동이 안 되던 오류**: 공용 `header.js`의 submit 이벤트에서 `search.html?keyword=검색어`로 이동하도록 구현했는데도 일부 페이지에서 동작하지 않았습니다. 원인은 각 HTML 파일마다 pull로 가져온 공용 헤더 구조가 서로 달랐기 때문이었고, 페이지별 헤더 마크업을 통일한 뒤 정상 작동을 확인했습니다.
- **검색어(keyword)가 없을 때 null이 반환되던 문제**: `URLSearchParams.get("keyword")`는 값이 없으면 `null`을 반환해 이후 로직에서 오류가 났습니다. → `const keyword = params.get("keyword") || "";`로 기본값을 지정해 해결했습니다.
- **다른 팀원이 merge한 search.js와의 코드 충돌**: 병합 과정에서 이미 동작이 확인된 기존 구조와 다른 팀원의 변경 사항이 충돌했습니다. → 기존에 검증된 구조는 그대로 유지하고, 페이지네이션·빈 결과 처리 등 새로 필요한 기능만 선택적으로 가져와 합친 뒤 커밋해 해결했습니다.
